ShopPhoto 0.2.3 post-release review

Improvement proposals for 0.2.4 / 0.2.5

A code-verified list of performance, structure, color, workflow, and AI improvements. Every location below was checked against the tree on the audit date. Items the 0.2.3 plan already closed are not repeated here.

Target: 0.2.4 / 0.2.5 Platform: macOS · Windows · Linux Toolchain: Rust 1.92 · wgpu 29.0.4 · egui 0.35 Audited: 2026-09-03 Prior plan: improvement-plan.html
UI thread Thumbnail cache write PNG encode plus a full cache directory scan runs inside the frame on every thumbnail.
5 stalls Beach ball candidates Five synchronous main-thread paths can run for seconds after a settings change. PERF-04 lists them and how to identify yours.
37% of Rust in 3 files panels.rs, app.rs, and renderer.rs total 13,148 lines.
Adobe RGB Export gap only Soft-proofing via custom ICC already shipped in 0.2.3. Export encoding is what is missing.

What changed from the first draft of this review

  • PERF-04 is new. The macOS beach ball on settings changes was not covered by any item: PERF-01 is about frame hitching, which cannot block the main thread for seconds. The new item lists the five verified main-thread stalls and how to catch the one you are hitting.
  • PERF-02 is worse than described: the write runs on the UI thread, not just often. Promoted to the first item.
  • PERF-01 dropped the unmeasured "90%" figure and the garbage-collection wording. Profiling is now step one.
  • ARCH-01 to 03 no longer claim faster incremental builds. Rust compiles per crate, so file splits do not change that.
  • COLOR-01 is scoped to export. Custom ICC soft-proofing shipped as item D3 in the 0.2.3 plan.
  • COLOR-02 drops AMaZE. It is GPL code from RawTherapee and this repo is dual licensed. AHD from the paper only.
  • COLOR-03 was a UX item filed under color science. It is now UX-05.
  • UX-02 gained a catalog schema step because there is no stacking concept yet. Effort raised to L.
  • UX-03 names the real enum, LocalMask, not MaskKind.
  • UX-04 separates lossless (pure Rust) from lossy (libwebp, a native dependency).
  • Baseline numbers are now measured: 35,613 Rust lines, 301 test functions, and clippy with -D warnings in CI.

Filters hide cards only. Section headings stay so the numbering keeps its meaning.

1. Performance and storage

Main-thread stalls behind the beach ball, frame hitching during edits, and I/O stalls during import.

PERF-04 P1 Effort M Done

Find and remove the main-thread stalls behind the beach ball on settings changes

macOS shows the beach ball when the main thread stops servicing events for a few seconds. The proxy re-render on a slider change is not that: it runs at quarter resolution or less, and the perf notes record about 51 ms for open plus render on the X2D II file. So PERF-01 cannot explain a beach ball. These paths can, and each was verified to run synchronously inside the eframe update on the UI thread.

  • AI denoise shares the GPU with the viewport. Core ML is configured with MLComputeUnitsAll (coreml.m:7). Inference on a 100 MP frame runs on the same GPU the viewport is presenting to, so the next drawable can block the main thread for the length of the inference. Changing the camera denoise mode starts this (sync_ai_denoise, app.rs:2776).
  • Turning AI denoise off, or its result arriving, reopens the image on the UI thread. gpu_open frees VRAM, uploads about 200 MB of CFA data, rebuilds every texture, and renders (app.rs:2127, called from 2796, 3571, 3630, 3664).
  • The AI split compare builds a second complete renderer on the UI thread and uploads the RAW again (sync_ai_split_compare, app.rs:2889 to 2960).
  • The sidecar save 500 ms after an edit is synchronous. JSON write and rename, a SQLite open that runs migrations, and the optional XMP write beside the source (save_sidecar_if_due, app.rs:2645 to 2720). Milliseconds on a local SSD, seconds on a network volume or SD card when write XMP is on.
  • Thumbnails still streaming in from a folder scan each cost a PNG encode, a cache directory walk, and a SQLite open with migrations on the UI thread (PERF-02). A slider change during that window lands in the same stalls.
Catch the one you are hitting: next time the beach ball appears, run sample ShopPhoto 3 -file ~/Desktop/shopphoto-sample.txt in Terminal, or use Activity Monitor, select ShopPhoto, and choose Sample Process. The main thread's top frames will name one of the paths above.
  • Add a watchdog: time each section of update (job results, sidecar save, rerender, tile) and log any over 100 ms with its label. Cheap, permanent, and turns the next report into one log line.
  • Core ML: use CPU and Neural Engine on Apple silicon so inference does not contend with the viewport, and stop scheduling proxy re-renders while inference is in flight.
  • Move the CFA upload for AI results and the split-compare renderer construction into the worker, and swap the result in on a single frame.
  • Move the sidecar, XMP, and catalog writes to the existing sidecar sync worker. Open the catalog connection once and keep it instead of reopening and migrating per write.
  • PERF-02 for the thumbnail path.
Not measured: these are the candidates the code allows, ranked by how long each can plausibly block. The sample will tell which one is real. Fix that one first.
Status: Done 2026-09-03. (1) Watchdog: every section of the logic pass is timed; a frame over 100 ms (SHOPPHOTO_STALL_MS) logs a warning naming the slowest sections and the F12 overlay shows the last report. (2) A persist worker now owns every disk write the frame used to do: the debounced sidecar, XMP, catalog annotation and metadata rows, with one long-lived SQLite connection; on_exit flushes it. (3) Image opens, AI denoise results and the split-compare renderer are built on a worker thread that shares the compiled pipelines, then adopted on the UI thread in one frame; the export worker shares pipelines too. (4) Core ML compute units are selectable with SHOPPHOTO_COREML_UNITS. The override allows testing viewport contention. Verified: watchdog and persist tests, both headless smoke runs (open, and AI denoise with split compare), and the only stall the watchdog reported was the QA screenshot capture itself.
PERF-02 P1 Effort S Done

Move thumbnail cache writes off the UI thread and stop rescanning the cache on every write

When a thumbnail job completes, the app handler encodes a 512 px PNG and calls the cache store function on the UI thread, inside the frame. The store function then runs the budget check, which reads the whole cache directory, stats every file, and sorts by modified time. Importing a folder of 5,000 photos does that 5,000 times, each one blocking a frame.

Where: crates/sp-app/src/app.rs:2104-2123 (store_cached_thumb), crates/sp-app/src/app.rs:3689 (called from the ThumbnailReady handler), crates/sp-catalog/src/thumbnails.rs:16-58 (store and enforce_budget)
  • Encode and store from the thumbnail worker, not the UI thread. The handler should only receive the ready texture.
  • Run the budget check once per scan batch, on idle, and at shutdown, not per write.
  • Keep a running byte total in memory so the check does not need a directory walk to decide it has nothing to do.
  • Optional: try QOI or lossless WebP for the thumbnail payload if PNG encode time shows up in the profile.
Verified: the call site is inside the job-result loop in the eframe update path. Together with PERF-04 this is the highest-value work in the review.
Status: Done 2026-09-03. The thumbnail worker now encodes the 512 px PNG and writes the cache entry itself (jobs.rs, cache_thumbnail); the UI handler only builds the egui texture. The budget walk runs when 64 MB of new entries have landed since the last walk, plus once per launch on a background thread (thumbnails.rs, enforce_budget_if_due). Catalog metadata rows from thumbnails and decodes go through the persist worker with one long-lived SQLite connection. Verified: sp-catalog tests for the interval and LRU order, and a headless open of a 50 MP file with a 16-image filmstrip showed no thumbnail-related stall in the watchdog log.
PERF-01 P1 Effort M Closed by measurement

Persistent uniform buffers and bind groups for the proxy render

The color buffers function builds every uniform buffer with create_buffer_init on each render, and the callers create fresh bind groups around them. Renders only run when the edit key changes, so this is once per slider tick during a drag, not once per displayed frame. On a 120 Hz display a drag can still trigger a render on most frames.

Where: crates/sp-pipeline/src/renderer.rs:1218 (color_buffers) and the create_buffer_init calls at lines 1277, 1320, 1328, 1412 to 1471, 1614 to 1695, 1822 to 1847
  • Profile first. Extend the perf budget tests to time a slider drag and record how much of a render is buffer creation versus compute dispatch. If it is under a few percent, close this item.
  • Allocate the uniform buffers once per loaded image with COPY_DST and update them with queue.write_buffer.
  • Cache bind groups and invalidate them only when a texture or its dimensions change.
Correction: the first draft claimed a 90% reduction and "garbage collection pressure". Neither is measured, and wgpu has no garbage collector. Deferred resource destruction is the real cost.
Status: Closed 2026-09-03 without the buffer change. A new perf-budget entry (proxy_render_cpu) measures the main-thread cost of a proxy render, which is where buffer and bind-group creation live: about 0.5 ms per render against a 10 ms GPU render on the development Mac. Persistent buffers could save at most a fraction of that and cannot affect a beach ball, so the plan’s own rule applied: under a few percent, close it. The budget stays in the test suite as a regression guard.
PERF-03 P2 Effort M Done

FTS5 index for catalog text search

The library query lowercases a concatenation of path, caption, keywords, camera, and lens and runs a LIKE with leading and trailing wildcards. That is a full table scan per keystroke. It is fine for a personal catalog of a few thousand images and becomes noticeable in the tens of thousands.

Where: crates/sp-catalog/src/catalog.rs:319-334
  • Add an FTS5 virtual table over those five columns with insert, update, and delete triggers on the photos table.
  • Enable the fts5 feature on the bundled SQLite build and add a migration step for existing catalogs.
  • Use prefix queries so live search stays incremental.
Status: Done 2026-09-04. A migration adds an external-content FTS5 table over path, caption, keywords, camera and lens with the unicode61 tokenizer, insert, update and delete triggers on photos, and a rebuild for existing catalogs; the bundled SQLite already compiles FTS5 in. The library query now matches photo ids against the index instead of a LIKE over a concatenation. Free text becomes quoted prefix phrases joined with AND, so IMG_00 still finds IMG_0001 and user input such as AND or parentheses cannot break the query; punctuation-only input is treated as no filter. Verified by tests covering prefix, case, multi-term AND, caption and keyword matches, metadata written after the scan, and rows removed by a rescan.

3. Color and RAW pipeline

One export gap and one demosaic quality option.

COLOR-01 P2 Effort S Done

Adobe RGB (1998) as an export color space

Export offers sRGB, Display P3, and Rec.2020. Print labs and fine-art workflows still ask for Adobe RGB. Soft-proofing against an Adobe RGB display profile already works through the custom ICC proof path that shipped in 0.2.3, so this item is only about encoding and the embedded profile.

Where: crates/sp-core/src/color.rs:14-19 (OutputColorSpace), crates/sp-export/src/encode.rs:11-21 (icc_profile via moxcms)
  • Add the AdobeRgb variant with Adobe RGB primaries, D65 white point, and the 563/256 gamma transfer.
  • Add the Rec.2020 to Adobe RGB matrix in the output transform and a round-trip unit test like the existing ones in color.rs.
  • Emit the matching matrix-shaper ICC from the same icc_profile function so JPEG, TIFF, and PNG embed it.
Verified: ICC embedding for JPEG, TIFF, PNG, and JPEG XL already goes through one function, which is why this is small.
Status: Done 2026-09-03. OutputColorSpace::AdobeRgb with the published D65 matrices (ADOBERGB_TO_XYZ, REC2020_TO_ADOBERGB and inverses) and the 563/256 transfer in sp-core color.rs; a Transfer enum tells the output shaders which OETF to apply through proof_flags.z, so exports are encoded with the Adobe gamma while the proof view stays sRGB. The export encoder embeds moxcms’ Adobe RGB (1998) matrix-shaper profile for JPEG, TIFF, PNG and JPEG XL; AVIF leaves CICP unspecified so viewers use the ICC. Export resampling and sharpening decode and re-encode with the Adobe gamma. The export dialog offers Adobe RGB (1998). Verified with five new tests: matrix consistency and transfer round trip (sp-core), CPU conversion of sRGB red, green and grey to the expected Adobe code values (sp-export), the embedded profile description and colorant (sp-export), and a GPU export of 18% grey in sRGB and Adobe RGB that decodes to the same linear value through each curve (sp-pipeline golden). Workspace total now 315 tests.
COLOR-02 P2 Effort L Done

Edge-directed demosaic (AHD) for 1:1 view and export

Bayer demosaic is Malvar (5×5 linear) for full quality and 2×2 superpixel for previews. Fine repeating detail can show color moiré and zipper artifacts under Malvar. An adaptive homogeneity-directed pass reduces both at higher compute cost.

Where: shaders/demosaic_malvar.wgsl, the superpixel dispatches in crates/sp-pipeline/src/renderer.rs
  • Implement AHD from Hirakawa and Parks as a compute shader: horizontal and vertical interpolation, then homogeneity selection in CIELAB.
  • Expose a "High detail" toggle in the Details panel that applies to 1:1 view and export only. Keep Malvar for the proxy.
  • Extend the golden-image tests with a synthetic CFA fixture that has a fine grid so the improvement is measured, not eyeballed.
Licensing: the first draft named AMaZE. That implementation is GPL from RawTherapee. Do not port it. AHD is published as a paper and is safe to implement from scratch.
Status: Done 2026-09-04. A new high-detail AHD compute pass builds horizontal and vertical color-difference candidates, scores their 3×3 neighbourhoods in CIELAB after as-shot white balance and the camera matrix, and selects the more homogeneous direction. The Detail panel toggle affects 1:1 tiles and full-quality tiled exports while the fast proxy stays on Malvar. A real-GPU synthetic fine-grid regression verifies that AHD reduces false chroma by at least 15% relative to Malvar.

4. Photographic workflow

Culling, external editors, masks, output formats, and on-canvas curve editing.

UX-01 P1 Effort L Done

Two-up and four-up compare for culling

The only split view today is the AI denoise before and after on one image. Choosing between frames in a burst or bracket needs two different photos side by side with locked pan and 1:1 zoom.

Where: crates/sp-app/src/hdr_view.rs (HdrBlitPack, compare_mode), crates/sp-app/src/panels.rs (ai_compare_split)
  • Allow two or four selected images in the filmstrip and grid.
  • Render each into its own proxy texture and tile the viewport, with an optional pan and zoom lock.
  • Add promote and reject keys that act on the focused tile.
Note: this is the most expensive P1 in the list. It stays P1 because culling is a daily task, but it is a judgment call, not a defect.
Status: Done 2026-09-04. Selecting two to four catalog or filmstrip photos enables a two-up/four-up culling view. Each cell owns an independently developed proxy and requests a 1:1 tile when zoomed; pan and zoom can be locked or independent. Click and arrow keys focus a cell, Enter or double-click opens it, and P, X, U and 0–5 persist picks, rejects and ratings to its catalog row and sidecar.
UX-02 P2 Effort L Done

Edit in an external editor and bring the result back

Compositing and retouching beyond ShopPhoto's tools happen in Photoshop or Affinity. The round trip should produce a TIFF, open it, and re-ingest the saved file next to the original.

Where: crates/sp-app/src/app.rs, crates/sp-catalog/src/workflow.rs, crates/sp-catalog/src/catalog.rs
  • Add a stack or companion relation to the catalog schema. There is none today, so the "ingest as companion" step needs it first.
  • Export a 16-bit TIFF in the active color space, spawn the chosen editor, and watch the file.
  • On save, add the TIFF to the catalog as a companion of the RAW and select it.
Correction: effort raised from M to L for the schema and watcher work.
Status: Done 2026-09-04. A catalog migration adds a durable source-to-companion relation. The External editor menu exports a dedicated 16-bit TIFF in the active color space, launches either a chosen application or the system default, and watches the rendered file for saves. A saved TIFF is ingested, linked to its RAW, selected in the library, decoded through the rendered-image thumbnail fallback, and marked with a TIFF companion badge. Regression coverage includes relation survival across rescans and macOS path aliases.
UX-03 P2 Effort M Done

Color range mask

Local masks are brush, radial, linear gradient, and luminance range. There is no way to isolate a hue such as sky, foliage, or skin.

Where: crates/sp-core/src/edit.rs:784-804 (LocalMask), shaders/retouch.wgsl
  • Add LocalMask::ColorRange with a target in Oklab a/b, a radius, and a feather.
  • Add an on-canvas dropper that samples the proxy texture to set the target.
  • Evaluate it in the retouch shader alongside the luminance range mask.
Status: Done 2026-09-04. LocalMask::ColorRange stores an Oklab a/b target, radius and feather. The Develop panel creates and edits the mask, and its on-canvas dropper samples one proxy pixel into the same transform used by the retouch shader. Unit and real-GPU tests cover serialization, clamping and isolation of the sampled hue.
UX-04 P3 Effort S Done (lossless)

WebP export

Export supports JPEG, TIFF, PNG, AVIF, JPEG XL, and Ultra HDR. WebP is missing.

Where: crates/sp-export/src/lib.rs:54-82 (ExportFormat), crates/sp-export/src/encode.rs
  • Add ExportFormat::WebP { lossless, quality }.
  • Lossless first, using the pure-Rust encoder in the image crate, with the ICC and EXIF written as RIFF chunks.
  • Lossy needs libwebp, a native dependency. Put it behind a cargo feature and confirm the Windows and Linux builds before turning it on by default.
Status: Done 2026-09-03 for lossless. ExportFormat::WebP { lossless } encodes through the pure-Rust encoder in the image crate with the ICC profile and EXIF embedded as RIFF chunks, and the export dialog offers WebP. Lossy WebP still needs libwebp; selecting it returns a clear error instead of silently writing lossless, and the UI only offers lossless until a native encoder is added behind a cargo feature. Verified by a round-trip test that decodes the file, checks the pixels are bit-exact and the ICCP chunk is present, and that lossy reports the missing encoder.

  • Sample luminance from the proxy texture at the pointer.

5. AI models

Subject and sky masks require a model that can be shipped.

AI-02 Blocked Effort L Blocked

Subject and sky masks from a segmentation model

One-click subject, background, and sky masks would remove most brush work for local adjustments. A small quantized ONNX segmentation model on the proxy frame is enough, and the tract-onnx runtime is already a dependency.

Where: crates/sp-ai/src/lib.rs, crates/sp-core/src/edit.rs (LocalMask)
  • Pick a model with a license on the existing allowlist and ship it through the same manifest path.
  • Add a LocalMask::Raster variant holding an 8-bit alpha texture so the retouch shader can consume it.
Status: Blocked after licensing audit 2026-09-04. Candidate weights either lack an explicit redistribution license, inherit noncommercial segmentation terms, or do not provide the required one-click subject and sky classes. A repository license for inference code is not sufficient authorization to bundle its weights. Add the raster-mask path only with a provenance-checked model and a committed license, version and SHA-256 entry in the existing manifest.
