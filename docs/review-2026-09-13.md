# Performance, reliability, formats, and masking review

Reviewed the existing working tree in place; earlier uncommitted work was preserved.

## Fixes

- PNG mask import now uses explicit transparency when present and luminance otherwise. Both 8-bit and 16-bit coverage work; 16-bit values remain intact. Previously RGBA transparency was discarded.
- Mask rendering and the coverage overlay prepare repair-stroke bounds once per region and skip strokes outside each pixel's area of influence. Sampling retains the original feathering, stroke order, inversion, and aspect-ratio behavior. Non-finite coordinates return zero coverage.
- The overlay samples pixel centers, matching the renderer, and its cache key now includes mask dimensions and stroke point counts.
- JPEG and Ultra HDR export reject dimensions above 65,535 pixels per side before encoding instead of truncating or clamping them. Export validation also rejects empty images and inconsistent 8/16-bit buffers. Constructors use checked dimension arithmetic.
- Exports use unique temporary files beside the destination, clean them up on failures, and atomically replace the destination only after encoding succeeds. Concurrent exports no longer share a predictable temporary pathname.
- Cached denoise loading bounds reads and checks the actual byte count before slicing, avoiding a panic if the file changes while being read. It also avoids cloning the original sensor buffer only to immediately replace it (about 200 MB of unnecessary copying for a 100 MP RAW).

## Validation

- `cargo test --workspace`: 351 tests reported passed, including app, shader compilation, GPU golden-image checks, codec round trips, and the default GPU performance budgets.
- Subsequent focused tests passed for cache integrity and capture-parameter preservation, hard-brush boundary equivalence, and export failure cleanup/destination preservation.
- `cargo test -p sp-core mask::tests -- --include-ignored --nocapture`: all six mask tests passed. The synthetic 256 × 256 benchmark with 24 repair strokes of 48 points each measured about 179 ms for the original sampling path and 1.7 ms with prepared bounds, with identical output. This measures CPU mask sampling, not whole-app frame rate; gains depend on stroke coverage.
- The installed enhancement virtual environment passed both numerical Python tests. Two optional real-model tests were skipped. The default system interpreter lacks OpenCV.
- `git diff --check` passed.

## Verification limits

This pass does not establish that the project has no remaining defects. Real-camera integration harnesses return early without `SP_TEST_RAWS`, `SP_TEST_SONY_RAWS`, and `SP_TEST_PREVIEW_RAW`; those variables were unset and no matching RAW fixtures were found in the tracked workspace. Decoder extension recognition does not prove support for every camera or compression variant. The normal editor entry point still accepts RAW files; catalogued external-editor TIFF derivatives do not acquire RAW editing support from these changes.

No manual GUI session, Windows/Linux run, or real-model segmentation-quality evaluation was performed. Dense or image-spanning repair strokes can still require substantial CPU sampling work. The optional real-model tests and representative camera originals remain the main validation gaps.
